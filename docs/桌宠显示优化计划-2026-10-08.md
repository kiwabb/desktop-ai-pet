# 桌宠显示优化计划

日期：2026-10-08。状态：规划稿；本轮只新增这份文档，不修改界面，不创建 Trellis 任务。

## 目标与方向

保留当前猫的素材、姿态、表情、动作和已保存主题。围绕现有温暖、可爱、圆润的界面，做到正文更好读、操作更轻、猫与话泡更自然、状态更可信。保留独立透明窗口、单一猫主体和 Lucide 图标。

优先改善日常聊天体验，再处理边缘场景和细节。不通过缩小文字或扩大默认窗口来换取阅读空间。

## 当前判断的依据

- **本轮原生观察：** 当前应用显示“正在读取助手状态…”，同时正文已经出现欢迎语和快捷提问，发送按钮禁用。这只能证明加载画面的表现，不能证明历史为空、模型可用或真实交互正常。
- **当前源码复核：** 紧凑标题、单行输入与发送、浅化色面、动态气泡连接和工具状态区分已经存在。以下计划将它们列为待验收措施，不重复认定为尚未修复的缺陷。
- **仍缺证据：** 同条件阅读面积实测、完整原生交互、左右与尺寸矩阵、各主题实际呈现和真实模型发送链路。

## 优化项目

### 1. P1：把加载、空历史和不可用状态分清楚

**当前问题：** 读取助手状态时，正文已经呈现欢迎页；用户无法从主阅读区判断对话是否仍在恢复。

**计划：**

- 首次读取期间显示明确、轻量的恢复提示；历史读取完成且确实为空时才出现欢迎语与快捷提问。
- 等待系统授权、连接不可用和普通读取中使用各自真实原因，避免同一条加载文案长期占据界面。
- 保留可编辑草稿；发送不可用时给出原因和对应入口，避免正文、输入区重复报告同一个问题。

**验收：** 启动 → 读取 → 有历史／真实空历史／连接异常，每个状态含义明确；状态切换不清空草稿、不将加载结果当成空数据。系统授权与模型连接恢复后，验证真实路径。

主要范围：[ChatPanel.tsx](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ChatPanel.tsx)、[ConversationFeed.tsx](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ConversationFeed.tsx)、[ChatComposer.tsx](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ChatComposer.tsx)。

### 2. P1：提高紧凑模式的实际阅读效率

**当前基础：** 标题和输入区已压缩，输入与发送已经同行；原生有效阅读高度尚未实测。

**计划：**

- 保留 420×380 紧凑阅读面板、14px 正文和至少 32px 的操作目标。
- 先测现有布局；长回复、连续消息和真实工具结果仍显拥挤时，统一调整消息间距、辅助信息与卡片内边距。
- 多行草稿按内容增长并设上限；错误或断连提示出现时，输入与发送保持可达。
- 检查工具详情与外层消息列表的滚动关系，保证“回到最新”容易找到且行为正确。

**验收：** 相同窗口、主题、字体、单行输入和连接状态下，对比有效阅读高度，目标较有效旧基线增加至少 25%。没有可比基线时只报告实际尺寸，不宣称增幅达标。长内容不截断，正文不缩小，发送后保持紧凑模式。

主要范围：[ChatBubbleFrame.css](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ChatBubbleFrame.css)、[ChatInteraction.css](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ChatInteraction.css)。

### 3. P1：让猫与面板在不同位置都贴合自然

**当前基础：** 已有左右连接、动态预留和窄空间回退；这些算法尚未完成原生矩阵验收。

**计划：**

- 空间充足时，话泡尾部自然指向猫的鼻口附近，保持短、圆润的形态。
- 屏幕边缘或窄工作区优先保证正文和控件完整；侧面不足时使用可用的上下区域，不强行拉长尾部。
- 猫的位置只随用户拖动或明确尺寸设置变化；打开、展开、关闭面板不推动猫。
- 同时核对窗口边界、阴影裁切和点击区域，不能只看孤立组件图。

**验收：** 左右两侧 × 80%／100%／120%，加四个屏幕边缘和窄工作区；猫与面板在同一实际桌面画面中可见，无猫身遮挡、控件越界或重开位移。物理空间确实不足时明确记录限制。多显示器只报告实际测试过的条件。

主要范围：[companion-attachment.ts](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/lib/companion-attachment.ts)、[window_geometry.rs](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src-tauri/src/window_geometry.rs)。

### 4. P2：统一视觉轻重，保留主题个性

**当前基础：** 输入区、消息与工具卡色面已经减轻，操作条也已减少阴影；实际主题兼容性仍需确认。

**计划：**

- 正文作为主要视觉焦点，导航与工具卡降低竞争；减少重复边框、背景和阴影，不增加装饰容器。
- 对齐猫脚边操作、面板导航、输入和工具卡的圆角、留白与图标尺度。
- 校验当前三花主题、旧单色主题及现有 AI 主题，保留用户保存的颜色和材质选择。
- 分别检查明暗桌面背景下的正文、输入边界、禁用态和键盘焦点。

**验收：** 普通正文对比度至少 4.5:1，关键控件边界与焦点至少 3:1；界面保持温暖可爱，猫仍是单一主体。主题持久化不被覆盖；没有实际保存的主题分支只标注静态检查，不能声称原生通过。

主要范围：[ChatBubbleFrame.css](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/components/ChatBubbleFrame.css)、[desktop-shell.css](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/desktop-shell.css)、[customization-theme.ts](/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src/lib/customization-theme.ts)。

### 5. P1：完成显示与交互的连续性验收

**当前基础：** 代码支持草稿、光标恢复和工具状态区分；最终运行版本的完整流程尚未证明。

**计划：**

- 串联中文输入、换行、发送、流式回复、工具展开、页签往返、展开收起和隐藏重开。
- 确保已发送内容立即可见，流式更新可追踪；用户向上阅读时不被强行拉回底部。
- 工具执行成功与业务完成分开：查询显示“已查询”，记录显示“已记录”，只有待办确实完成才显示“待办已完成”。
- 错误、重试和历史恢复使用真实状态与现有数据；保留草稿、光标及用户设置。

**验收：** 最新源码对应的原生进程完成上述路径；真实模型发送、流式返回与只读工具查询分别有匹配证据。模型未恢复时仅验收不可用状态，不能替代在线验收。验证不新增待办、备忘录或模拟回复。

## 执行顺序与交付标准

1. 固定当前主题、窗口尺寸和位置，保存有效基线；先完成加载状态区分与阅读实测。
2. 根据实测一次性调整内容密度、视觉层级和贴合问题，保留既有有效措施。
3. 批量验证尺寸、边缘、主题和完整原生路径；测试结束恢复原来的用户偏好。
4. 由未参与实现的全新独立 agent 复核匹配运行版本的实际效果；发现的问题集中修正并复验。

交付包含同条件前后画面、实际测量、原生流程结果与独立评审。源码检查、单测、预览和构建结果各自标明，不能替代真实运行证据。

本轮交付只有这份计划；界面实现、系统授权、模型连接设置与数据均不变。
