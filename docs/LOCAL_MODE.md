# 单机模式说明

单机模式在桌面应用内运行 Rust 助手，将聊天、待办、备忘和执行记录保存到本机 SQLite。模型由你配置的兼容接口提供，不需要 Python 服务或外部数据库。

首次运行步骤见 [README](../README.md#开始使用)。本文说明配置、数据、上下文和使用边界。

## 模型配置

打开 **聊一会 → 连接设置 → 单机**，填写模型服务地址、API Key 和模型标识，然后选择 **保存并连接**。

| 项目 | 规则 |
| --- | --- |
| 服务地址 | 兼容接口根地址，通常以 `/v1` 结尾；应用追加 `/chat/completions` |
| 传输 | 远程地址必须使用 HTTPS，`localhost`、`127.0.0.1`、`::1` 支持 HTTP |
| API Key | 保存到系统凭据存储；macOS 使用 Keychain |
| 模型标识 | 使用服务实际支持的标识；模型列表依赖服务提供 `/models` |
| 兼容能力 | 需要流式 Chat Completions；待办、备忘和历史查询还需要工具调用能力 |

当前发送就绪检查要求地址、API Key、模型三项都非空。使用无鉴权的本地模型服务时，也需要满足这个配置要求；是否接受请求中的凭据字段由该服务决定。

在同一服务地址下，API Key 留空会复用已保存的密钥。更换服务地址不会继承旧服务的密钥，需要为新地址重新配置。读取或保存钥匙串时，系统会按自身权限规则处理授权。

默认请求超时为 90 秒，默认日期解释时区为 `Asia/Shanghai`。当前设置界面提供地址、密钥和模型编辑；这些高级默认值由 Rust 配置定义。

## 聊天与工具

普通回复会逐步显示并保存在本机。工具执行通过同一段对话显示状态；只有真实执行成功，助手才能确认保存。

| 对话能力 | 可执行操作 |
| --- | --- |
| 待办 | 创建、查询、完成；设置、修改或取消一次性提醒 |
| 备忘与长期目标 | 创建、查询、修改、归档或取消归档；设置、修改或取消回顾时间 |
| 历史 | 查询当前本机会话中、本轮请求以前的聊天原文 |

待办和备忘列表提供直接操作入口，不调用模型。工具修改记录时需要真实记录 ID 和必要的状态校验；历史回复或摘要不能代替当前查询结果。

应用运行时约每 15 秒检查本地待办提醒和备忘回顾。这些检查读取 SQLite，不依赖远程模型响应。退出期间不会实时提醒，重新运行后检查仍未处理的到期记录。

## 上下文与历史

**数据库里保存的历史，比每次发给模型的内容多。** 上下文管理只选择输入，不删除原始记录。

| 部分 | 当前规则 |
| --- | --- |
| 普通输入目标 | 6,000 个估算 token，包含系统说明、消息和工具定义 |
| 优先保留 | 当前消息、最近两轮完整对话、未完成任务的真实工具记录，以及本轮工具调用与结果 |
| 旧原文选择 | 从近期完整轮次中按预算选择；每个模型步骤重新计算 |
| 必要内容超额 | 保留原文并记录超额，不静默截断当前输入或工具回执 |
| 历史来源 | 原始时间、消息或任务 ID、角色与状态，用于核对旧事实 |
| 检索 | 按字面片段匹配；每次最多 10 条，每条最多 600 字符，标注截断与更多结果 |

估算值用于控制体积，不等于模型实际计费 token，也不代表模型的上下文上限。模型返回实际用量时，应用单独记录数字指标；不提供用量时不会把估算值冒充实际用量。

### 后台摘要

可摘要的旧对话达到 6 轮，或达到约 4,000 个估算 token 后，应用才尝试生成增量摘要。最近两轮保持原文。摘要使用当前配置的模型和已有历史，不调用业务工具，不自动创建备忘。

摘要请求最多使用 6,000 个估算输入 token，并限制输出长度。新消息到来时，应用取消后台摘要，优先处理聊天。每条摘要事实需要带实际来源 ID；保存时检查来源范围和版本，旧任务不能覆盖新缓存。

以下情况保留原文和此前缓存，正常聊天继续：

- 历史未达到摘要阈值。
- 模型调用失败，或摘要格式、来源校验未通过。
- 最旧的单个待摘要轮次已超过摘要输入预算；应用不会跳过它却声称已经覆盖。

历史中的相对日期应依据原文明确日期和完整的历史时间依据解释，不能按今天重算。时间依据不足时保留原说法，不猜日期；用户事实和原始对话优先于助手后续概括。

## 本机数据

macOS 数据目录为 `~/Library/Application Support/ai.desktop.pet.juban/`。

| 文件或存储 | 内容 |
| --- | --- |
| `agent-local.db` | 原始聊天、任务状态、工具结果、待办、备忘、摘要缓存与数值指标 |
| `agent-config.json` | 连接配置；单机 API Key 不以明文写入该文件 |
| `companion-preferences.json` | 桌宠大小和置顶偏好 |
| 系统钥匙串 | 单机模型 API Key |

备份前先退出应用，保存整个应用目录。换设备时，数据库和配置文件不能代替系统钥匙串中的密钥，需要重新配置模型凭据。

单机数据与服务端账号数据相互独立。切换模式不会自动复制聊天、待办或备忘，也不会自动进行云同步。

原始记录保存在本机，但选择远程模型时，应用会将本次选中的消息、工具定义和相关执行结果发送到该接口。后台摘要也会将其源对话发送到同一接口。

## 常见问题

### 保存后仍不能发送

检查是否选择 **单机**，并确认服务地址、密钥、模型均已填写。保存配置只说明配置已保存；发出一条真实消息并收到回复，才证明模型请求成功。

### “正在保存”停留较久

保存或复用 API Key 时需要访问系统钥匙串。先检查系统是否正在请求授权，不要连续重复保存。当前保存路径会等待系统凭据操作结束；这个阶段尚未开始模型请求。

### 获取不到模型列表

模型列表依赖服务的 `/models` 接口。确认服务支持该接口，或直接填写提供方给出的模型标识。不要把“能获取列表”当作聊天和工具调用均已验证。

### 助手找不到很早的细节

请指出要回顾的主题或一段原文关键词，让助手查询历史。当前检索是有限的字面查询；摘要也会遗漏信息，不能保证完整回忆。重要事项可以明确要求保存为待办或备忘。

### 应用重启后没有继续上次的操作

重启会恢复记录，并将未完成任务标记为中断。应用不会自动重放业务操作，以免重复创建或修改事项。先查看已保存结果，再决定下一步。
