# 后台与链路追踪修复

## 目标与授权
用户在完整复查报告呈现后明确要求“你改好吧”，本任务按已评审 F1–F15 和其他管理边界修复，不重开产品范围讨论。原功能目标仍为内部管理、仅服务端追踪、模型配置编辑/测试/发布/回滚。

## 范围
- 修复报告全部 F1–F15：模型状态锁/审计 SQL 与枚举、真实流式测试验证、发布 Key 验证、版本超时、观测隔离/取消/缺口/完整快照/Token/脱敏/partial、完整追踪 UI、分页、幂等与复制失败。
- 统一敏感正文 POST+CSRF+审计+no-store；补回滚 Key 选择与审计种类；有界登录限流。
- 保持现有业务事务、设备协议、单机模式和未提交桌宠动效改动。

## 验收
1. 无上述已知阻断；关键 SQL 经真实 PostgreSQL 检查，新旧配置绑定/审计/发布的隔离测试不能替代真实证据。
2. 不再因追踪锁等待拖垮业务；取消终态、部分输出、缺口持久且可见。
3. 后台真实时间线按因果顺序、Token 和延迟正确、工具可检查；切换无串数据、分页和刷新恢复、流式更新可暂停跟随。
4. 无假数据服务、未批准的临时数据库或自动生成业务样例。实际环境无法验证部分明确报告，不宣称端到端通过。
5. 质量检查后独立复查，按作用域提交；不混入桌宠动效文件。
