# 实施与验收顺序（已确认，进入实现）

同一纵向功能采用本任务下分阶段验收，不拆独立子任务：存储、生成、界面均不能单独代表用户目标完成。下列依赖明确，未来并行代理只在契约固定后分配互不重叠文件。

1. 固定IPC/manifest/theme/job契约与失败语义；读取desktop/frontend规范。原工作区开发，保留发布副本用于后续白名单同步，绝不推旧私有历史。
2. Rust资产存储、输入校验、原子保存、活动revision和默认方案。新增独立模块；验证坏文件、路径边界、取消迟到结果、旧配置兼容。
3. 依赖2：图片服务设置/凭据、真实edits适配器、四阶段生成与显式重试。存储失败不激活；与聊天worker隔离。
4. 依赖1可做组件，依赖2/3后联调：上传、生成状态、预览、主题主色、方案管理；接入菜单/面板导航。不得用假成功UI代替服务联调。
5. 依赖2/4：PetStage/PetExpression读取动态素材，主题传播所有当前面板，旧默认完全保留。检查尺寸、透明边缘、落脚点和reduced-motion。
6. 实现代理完成后由check代理复核；若代理服务额度不可用，披露并由主线程按相同范围检查，不能声称独立审查通过。
7. 静态：pnpm test；cargo test --manifest-path src-tauri/Cargo.toml --lib；pnpm build。重点覆盖任务竞争、坏图、异常持久化、revision乱序、导航草稿和默认恢复。真实模型流与窗口需要下一步独立证据。
8. 原生：构建准确版本，用户在应用配置真实图像服务并选择真实参考图；实际生成→四状态预览→全主题应用→聊天/待办/备忘/设置→关闭重开→重启→恢复默认。记录费用/请求计数、模型与证据类别；不记录密钥。不创建临时业务数据库或伪造数据。
9. 完整R1–R7逐项审计，更新README真实使用说明；若请求发布新功能，仅从已验证白名单同步发布副本，审查diff后提交/push。当前授权已明确发布单机基线，后续定制发布范围在最终验收时核对。

回退：关闭新入口并切default preset可恢复既有体验；不要回滚业务数据或删除用户保存的方案。风险文件：App.tsx、PetStage.tsx、PetExpression.tsx、design-tokens.css、ChatBubbleFrame.css、src-tauri/src/lib.rs、Tauri资产权限配置。

开始前：最终方案获用户确认后才运行task.py start；implement.jsonl/check.jsonl必须包含真实规范与研究路径。
