# 待办功能完善：手动增删改 + 提醒快捷选项 + 分组视图

## Goal

待办列表从"只能看 + 完成 + 设提醒"升级为完整的增删改查；提醒设置提供快捷时间选项；列表按待完成/已完成分组。两种模式（服务端/单机）能力对齐。

## Requirements

### R1 手动添加
- 待办列表页顶部常驻输入框，输入标题回车/点按钮即创建（不经模型）。
- 标题校验 1..2000 字符（与服务端工具规则一致）；创建后出现在待完成分组。

### R2 删除
- 每行提供删除入口，硬删除，点击即生效（配淡出动画），不做二次确认弹窗。
- 服务端模式：新增 `DELETE /v1/todos/{todo_id}`；单机模式：本地 store 删除。

### R3 编辑标题
- 每行可进入行内编辑，保存走校验（1..2000）。
- 服务端模式：新增 `PATCH /v1/todos/{todo_id}` `{title}`；单机模式：本地更新。

### R4 提醒快捷选项
- 提醒编辑器增加快捷 chips：`今晚 20:00`、`明天 09:00`、`明天 20:00`、`下周一 09:00`、`自定义`（保留 datetime-local）。
- 快捷项若计算结果非未来时间则自动顺延到下一个候选日；仍走现有 expected_remind_at CAS 流程。

### R5 分组与排序
- 待完成在前：按 提醒时间升序（无提醒排后，按创建时间升序）。
- 已完成折叠为底部可展开分组，显示数量，组内按创建时间倒序。

### R6 动效与空态
- 新增行淡入、删除淡出、完成勾选过渡（CSS transform/opacity，合成器友好）。
- 空态保留现有引导文案。

### R7 双模式对齐
- 服务端模式新增 `POST /v1/todos`（`{title}` → `{item}`）、`PATCH /v1/todos/{id}`、`DELETE /v1/todos/{id}`，沿用 Bearer 认证 + `{"detail"}` 错误格式 + 现有状态码映射。
- 单机模式 local store 实现同等语义。
- Rust 新增 command：`agent_create_todo` / `agent_update_todo` / `agent_delete_todo`，按 mode 分发，签名两模式一致。

## Acceptance Criteria

- [ ] 两种模式下均可手动添加、删除、改标题，刷新/重启后状态正确。
- [ ] 提醒快捷选项生成的目标时间合法（未来时间）且写入走 CAS；冲突文案不变。
- [ ] 分组排序符合 R5；已完成组默认折叠。
- [ ] 服务端新增端点有 pytest 覆盖（认证、校验、404、成功路径）；`tools/verify-agent-service.py` 不回归。
- [ ] 前端五个验证脚本全绿 + `pnpm exec tsc -b` + `cargo check/clippy/test` 全绿。
- [ ] 删除不影响模型工具路径（todo_create 等 4 个工具行为不变）。

## 非目标

- 不做撤销（undo）、不做拖拽排序、不改到期提醒横幅形态、不做标签/优先级。
