# 气泡框抽象复查（2026-09-07）

## Conclusion

现有抽象已完成主要代码迁移，但完整封装验收尚未通过。以下问题为当前源码与真实 Chromium 对既有 QA 页的浏览器层探针证据；不是 Tauri 原生交互或真实模型调用证据。此次未修改产品代码，未调用模型，未新增或发送假消息。既有 QA 页含 fixture，检查范围仅为布局、CSS 状态和快捷提问/按钮状态。

## Findings

1. **P2 — 全局桌面定位污染普通容器。** `src/styles.css:282-285` 为全部 `.chat-panel` 设置 absolute 和桌面 inset。既有 `?view=frame&mode=compact` 无桌宠祖先，但移除宿主 inline inset 后，computed style 仍是 `position:absolute; top:10px; right:10px; bottom:152px; left:10px`。应将坐标规则限定于真正的桌面宿主或调用方显式布局类。
2. **P2 — 自带样式缺少尺寸 reset。** `src/components/ChatBubbleFrame.css:95-110` 的 standalone compact 标题行固定 48px，标题 min-height48 加上下 padding9 和 border1。移除 QA 加载的 `/src/styles.css` 后，实测 `boxSizing=content-box`、标题高度58、headerBottom218.5、bodyTop208.5，标题侵入主体10px。组件需要自己的局部 border-box。`qa/chat-preview.tsx:9` 仍导入应用全局样式，因此原 AC1 通过不能证明只加载组件样式也成立。
3. **P2 — 组件 reduced-motion 覆盖无效。** `src/components/ChatBubbleFrame.css:369-370` 的两类选择器优先级低于 `:361-366` 的四类入场选择器。在只保留组件 CSS 的既有中性预览 DOM 上设置 attached/entering 并模拟 reducedMotion=reduce，实测媒体匹配 true，但 animationName 仍为 component-chat-bloom、duration0.3s。全局 reduced-motion 的 !important 掩盖此缺陷。组件媒体查询必须独立覆盖真正生效的选择器。
4. **P2 — 可见性恢复不重播入场动画。** `src/components/ChatBubbleFrame.tsx:55` 使 entering 类独立于 visible 保持不变。浏览器对其实际 class/inert 映射执行 hidden→visible 后，动画 startTime 前后均为75491.47100000118、playState 均为 finished。该结果为 DOM/CSS 状态探针；源码确认 props 渲染使用同一映射。与设计中“可见性恢复时应能重播”不符，应令隐藏阶段不持有生效动画声明，并明确 standalone 的 animateEntrance 语义。
5. **P2 — 既有 QA 调用契约已过期，不能用来验收发送。** `qa/chat-preview.tsx:64-78` 仍传旧 source/onStatusChange 与 Promise 形式 onSend，缺当前 connection/model_configured/acceptedRequestId。现行契约在 `src/components/ChatPanel.tsx:37-52`、发送条件在 `:147`。浏览器点击“帮我分析”后 textarea 确有文字但“发送消息”仍 disabled。这是并行 agent 接入后的 QA 集成遗漏，不应归因于 Frame 的业务实现。QA 不在 tsconfig.app.json include 内，正常 pnpm build 不覆盖这个调用方。
