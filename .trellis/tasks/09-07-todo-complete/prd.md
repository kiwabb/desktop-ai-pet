## Requirements

- R1：新增 todo.complete 工具，模型调用名 todo_complete，参数 todo_id 为已有记录 UUID；仅可修改认证账号自己的记录。
- R2：用户明确指定事项且能唯一定位时执行；仅说“完成待办”、目标缺失或同名歧义时询问具体事项。不能猜测 ID 或批量完成。
- R3：pending → completed；重复完成同一事项返回其当前已完成状态，不新增记录。状态修改与工具成功结果同事务。
- R4：查询仍返回原有记录，包括已完成项，明确展示“待完成/已完成”。保留历史记录。
- R5：沿用消息、任务、工具事件和快照合同；完成成功后才回复成功，失败必须保持真实状态和错误。

- R6：在现有聊天框增加“待办列表”按钮，打开同一气泡框内的列表视图，可返回聊天；保留聊天历史、草稿和正在运行的任务。
- R7：列表通过 Rust 原生层调用 GET /v1/todos，设备凭证不进入 WebView；不调用 Agent，不发送聊天消息，也不创建 agent run/tool call。模型未配置时，只要服务端认证与查询可用，仍可查看。
- R8：展示标题、待完成/已完成状态和创建时间，提供刷新；加载中、真实空结果和查询失败必须区分。打开时获取数据，切换服务或账号时清除旧列表，旧请求不能覆盖新账号的数据。
- R9：待完成事项旁提供“完成”按钮，直接调用认证接口，不经过 Agent；处理中防重复点击，成功后显示已完成，失败保留原状态并呈现错误。已完成事项可点击同一完成框恢复为待完成，保存成功后才更新状态。
