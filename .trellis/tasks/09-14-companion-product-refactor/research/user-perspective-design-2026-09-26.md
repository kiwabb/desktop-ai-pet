# Research: 最新版桌宠的使用者视角设计评审（Assessment A）

- Query: 用户认为桌宠“不像合格桌面应用，也不像宠物，感觉奇怪”；最新明确要求评估最新版。
- Scope: internal；只读当前工作区相关实现及由主代理构建、启动的最新版 macOS 原生应用。独立 Assessment A，未接触检测器或 Assessment B 输出。
- Date: 2026-09-26
- Target: `src/App.tsx` 桌宠入口、closed / compact / expanded 相邻流程。
- Review mode: Operate，兼顾日常陪伴；Nielsen 十项均适用。
- Authority: PRODUCT、DESIGN、本任务 PRD/design/implement。保留已确认白猫、单猫及透明双窗口；没有修改代码/任务状态、运行测试或 git 操作。

## Findings

### 结论

用户的判断成立，而且最新版先存在一个比外观更基础的问题：主代理连续两次点击白猫，都没有完成打开聊天，约 5 秒后提示“聊天窗口未响应，请重试”。当前不能将它称为已可用的桌面助手。

独立的设计问题也有证据：它有明确的白猫形象，也有呼吸、眨眼和短暂状态变化，但主要互动仍是打开聊天入口；陈列式插画、整体运动、常驻连接状态和固定猫底盘共同强化“带猫插画的工具挂件”，宠物的身体反应和陪伴动机尚未形成可信闭环。换猫、换颜色、继续加装饰都不是直接解法。

### 证据等级和最新版本边界

- **最新构建来源（主代理验证）**：当前工作区 debug bundle；源码指纹构建起止一致。唯一运行 PID 65297，路径为 `/Users/zhoujiaangyao/zhoujiangyao/AI/desktop-ai-pet/src-tauri/target/debug/bundle/macos/橘伴.app/Contents/MacOS/desktop-ai-pet`。
- **本评审直接观察**：只读 CUA 选择上述 `.app` 并读取 closed 的 AX/截图。464×762 像素截图显示白猫、猫垫和圆盘、固定心星、顶部“陪着你 / 连接已断开”。最新 AX 为 pop up button，Help 明确包含点击/拖动/右键。
- **主代理真实操作证据**：第一次点猫先显示“很开心”，随后没有完成聊天打开，约 5 秒后提示“聊天窗口未响应，请重试”；第二次点击同样结果。两次来自同一次启动，不能称为跨重启复现。尝试退出再定位时工具超时，PID 未变，未证实重启。右键观察不充分，不判定右键失败。
- **未验证**：最新版 compact/expanded 正常呈现、双窗口合成、输入发送、模型/工具、长文、动画连续帧、屏幕阅读器、多 DPI。后文对这些区域只做源码设计判断。
- **未使用模拟数据**：没有请求模型，没有执行业务工具，没有创建 fixture、mock 或业务记录。当前断连是真实环境状态；“连接已断开”和“聊天窗口未响应”是两个不同提示，不能未经诊断合并根因。
- **排除旧安装版**：早先 `/Applications/橘伴.app` 的图像/控件与工作区不同，已从最终主要证据剔除。其时间和文案差异只说明版本漂移，不用于给最新版定性。
- **截图边界**：单窗口截图白底不能证明不透明；chat 单窗口中未见猫不能证明猫消失。本评审没有作这两种推断。

### 主要问题（4 项）

#### 1. [P0] 点击桌宠不能可靠进入对话，第一条使用路径被阻断

- **运行事实**：主代理操作最新版，两次点击均在约 5 秒后报“聊天窗口未响应，请重试”。没有成功打开 compact，无法继续使用主要功能。
- **源码定位**：`src/components/PetStage.tsx:37-40` 把点击交给互动/打开回调；`src/App.tsx:191-218` 建立跨窗口 request/reply，`:216` 的 5 秒计时器抛出同一文案；`:221-223` 保存错误，`:641-652` 经宠物状态区显示打开失败与重试入口。
- **判断**：这已足以判定本次最新版入口不可用。它不是“看起来不够像桌面软件”的审美分歧，是用户点击后无法进入产品。
- **边界**：原因尚未定位；不能从超时直接断言是 IPC、窗口层级、渲染、服务断连或哪一个模块坏了。第一优先级是修复并重新验证实际点击→可见面板→输入→收起闭环，不能用 build 或源码支持代替。

#### 2. [P1] 有猫的图像和动效，但互动没有建立宠物的行为逻辑

- **源码事实**：`PetStage.tsx:37-40,138-155` 每次激活都执行 `onPetInteract()` + `onToggleChat()`；`App.tsx:512-513,572-585,650-652` 将其落实为打开/激活聊天、700ms happy 后返回 agent 状态。`App.tsx:239-263` 的自主活动为每 7–16 秒随机 curious/sleeping，睡眠 3.2 秒、好奇 1.8 秒；`src/lib/pet-state.ts:23-38` 的主要状态由任务运行决定。
- **形象事实**：最新 closed 是正面坐姿猫与猫垫/圆盘/心星/状态牌的完整陈列构图。`PetStage.tsx:92-105` 把原图、状态、眼睑包在同一 accent/figure 中；`src/desktop-shell.css:61-103` 让整组呼吸、缩放、摇摆和点头；`PetExpression.tsx:40-45` 提供局部眼睑。
- **使用者推断**：摸它主要是进入任务入口，短暂开心不足以形成独立回应；短随机睡眠也缺少持续的生活逻辑。猫、底座和状态牌一起动，容易被读成整张贴纸/摆件在动，身体的生命感不充分。
- **准确表述**：不是“完全静止”或“没有自主行为”。已有动作，但用户操作、注意方向、身体反应与持续状态的因果关系偏弱。本轮未录连续帧，不能声称已证明掉帧、僵硬或眼睑错位。
- **设计方向**：保留白猫身份，优先定义一个不用打开大面板也完整成立的短互动，以及可持续的安静/休息行为。先验证因果，不先堆随机动画；资产分层或重绘不在本轮授权内。

#### 3. [P1] 轻陪伴与重阅读共用由猫台决定的空间，两个目标相互牵制

- **源码事实**：`src/desktop-shell.css:4-7,133-151` 将猫固定为 232×380.9、compact 框高 278、场景 713×401，expanded 仍为右侧猫台预留约 224px。`src-tauri/src/window_geometry.rs:4-8` 的首选聊天承载为 940×760；这是承载尺寸，不等于全部不透明区域。`src/components/pet-shell-geometry.ts:29-42,49-58` 让面板和猫盘共用带弯折与脚印的连续外形。
- **流程事实**：`ChatPanel.tsx:271-294` 每次 compact 发送被接受后转 expanded；`:428-455` 只在 expanded 显示会话内容。因此短句没有独立的轻量回答完成态，长文仍附着于固定角色侧栏。
- **使用者推断**：用户只是想随口一句，也进入较重的阅读工具；认真阅读时，又要为装饰和猫台支付持续空间成本。外形的一体感比使用意图的分层更强。
- **边界**：最新版实际 expanded 未打开，本项是源码设计判断；不宣称已发现溢出、屏幕越界或具体原生布局 bug。
- **设计方向**：先区分常驻、短互动、长文/工具三条流程的空间与注意力需要，再决定外壳如何从简洁入口进入工作区、完成后如何回落。保留单猫和透明窗，不以删功能换清爽。

#### 4. [P1] 常驻强调系统健康，轻入口又先陈列工具，陪伴关系退居次位

- **已见事实**：最新版 closed 显示“陪着你 / 连接已断开”。`src/lib/pet-live-status.ts:14-32` 优先显示配置/连接/设备/错误，情绪排在后面；`PetLiveStatus.css:40-56` 次级状态为固定 9px 单行省略。`App.tsx:525-550` 右键菜单只有重置和退出。
- **源码事实**：`ChatPanel.tsx:413-422` compact 首屏有历史/待办/备忘录/设置/关闭 5 个图标按钮；`ChatComposer.tsx:104-108` 再提供 4 个快捷提问。工具能力完整，但不是递进建立的主次关系。
- **使用者推断**：日常看它，最稳定的信息是后台服务健康；触碰它，首先面对功能目录。想专注工作时，当前目标范围内最明确的控制是拖走或退出，缺少易发现的持续安静意图。成功标准“愿意一直开着”尚未被常驻体验兑现。
- **边界**：不声称全应用/系统不存在其他隐藏途径；没有审查全部菜单。最新版 compact 未观察，五项导航和四项快捷按钮只作为源码事实。
- **设计方向**：状态仍要真实、故障仍要可恢复，但不应长期占据角色表达的中心；明确一项低门槛首次行为，并让次要工具逐步出现。

### 正在起作用的部分（3 项）

1. **角色身份成立**：白猫容易辨识，源代码主入口所有模式保持同一 reference 图（`App.tsx:641-653`），最新版 closed 实际相符。不应擅自换猫。
2. **没有假装在线或已完成**：最新版诚实呈现断连和打开失败；源码未配置/未连接/无模型禁用发送（`ChatComposer.tsx:32-33`、`ChatPanel.tsx:271-282`）。真实性值得保留。
3. **工具连续性已有代码基础**：Escape 分层返回（`ChatPanel.tsx:206-223`）、确认后清草稿（`:138-145`）、失败保草稿（`:295-296`）、历史和回最新（`:455-463`）、减少动效（`desktop-shell.css:105-108`）。这是源码优点，本轮没有把它说成原生已通过。

### 认知负荷与三条路径

- **认知负荷（源码）**：5 个标题动作超过单组 4 项参考值；加上 4 个快捷提问和发送，一屏约 10 个行动入口。输入/导航/快捷区有分组，但单一重点、最少选择、渐进呈现和分块四项不足。这相对于“随手摸猫、说一句”的低复杂度任务负荷偏高，不代表所有工具页都过于复杂。
- **首次使用（最新版实测）**：看到白猫 → 点击 → 短暂开心 → 对话未打开 → 5 秒后要求重试 → 再试仍失败。情绪高点在形象，结尾落在无效重试。
- **日常陪伴（closed + 源码）**：常驻形象 → 低幅呼吸/随机短状态 → 点击主要去聊天 → 关闭后回系统状态。已有动作，但独立的陪伴反馈与可持续安静意图弱。
- **长文/工具（仅源码）**：点猫/快捷提问 → 接受后 expanded → 读回复/工具 → 待办/备忘录 → 返回聊天 → 收起。阅读和草稿连续性设计值得保留；本轮无法进入，未使用模型或工具，不宣称该路径成立。

### Persona red flags

- 首次安装、非开发者：连入口都未能打开，不知道应重试、检查服务还是重开应用；这三者不能由用户自行猜测。
- 工作中的常驻用户：缺少独立安静陪伴，持久状态牌持续强调服务健康。
- 长文用户：固定猫台与内容空间争夺；仅源码判断，实际阅读未知。
- 键盘/低视力用户：aria/键盘入口是基础，9px 状态和仅图标控件有识别成本；未做屏幕阅读器验收。
