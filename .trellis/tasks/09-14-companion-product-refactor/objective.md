你的目标是：在保留现有项目核心功能、业务逻辑和可用性的前提下，对整个桌宠前端进行一次系统性的产品级重构与优化。

请尽你最大能力，将当前前端的【视觉表现、交互体验、动画反馈、桌宠融合度、布局细节、状态反馈、性能表现和代码质量】提升到成熟商业软件 / 工业级桌面应用的水准。

这不是简单的“美化页面”，而是要把它真正设计成一个完整、自然、有生命感的「桌面宠物产品」。

核心目标如下：

1. 桌宠定位优先\
   猫咪 / 桌宠必须始终是产品视觉和交互的核心，而不是页面旁边额外放置的一张图片或 SVG。

所有窗口、聊天框、Todo、设置、状态面板、快捷功能等 UI，都应该与桌宠形成自然的视觉关系和交互关系。

重点处理：

- 桌宠与窗口之间的连接、依附、探头、靠边、悬挂等关系
- 避免明显的“宠物 + 普通后台管理界面”拼接感
- 窗口展开、关闭、切换时，让桌宠产生合理反馈
- UI 的出现位置、圆角、阴影、层级和动画都要符合桌面宠物产品逻辑
- 桌宠不能被简单限制在普通卡片框内部

2. 视觉质量\
   整体视觉达到成熟商业桌面应用标准。

重点优化：

- 信息层级
- 字体与字号体系
- 间距系统
- 圆角体系
- 阴影
- 边框
- 毛玻璃 / 半透明效果
- 图标
- Hover / Active / Focus / Disabled 状态
- 空状态
- Loading 状态
- 错误状态
- 成功反馈
- 弹窗
- Tooltip
- 菜单
- 输入框
- 按钮
- 列表
- 滚动条

禁止出现：

- 廉价网页感
- 普通管理后台风格
- 大量生硬矩形堆叠
- 不统一的圆角、阴影、颜色和间距
- 为了“炫酷”而堆叠无意义特效
- 与桌宠主体割裂的功能窗口

视觉风格应精致、轻量、温和、有科技感，但不要过度卡通化。

3. 动画与微交互\
   建立统一的 Motion Design 体系。

所有动画必须自然、有物理感、有目的性。

包括但不限于：

- 窗口展开 / 收起
- 面板切换
- Hover
- 点击反馈
- 拖拽反馈
- 输入反馈
- 消息出现
- Todo 新增 / 完成 / 删除
- 设置项切换
- 桌宠状态切换
- 桌宠与窗口联动
- 错误提示
- 成功提示
- 弹窗出现 / 消失

避免：

- 所有元素同时移动
- 动画时间过长
- 弹跳过度
- 无意义缩放
- 影响操作效率的动画

优先保证 60FPS 和交互响应速度。

4. 桌面应用感\
   不要按照普通网页思路设计。

请按照 Windows / macOS 桌面 Companion App、Floating Assistant、Desktop Pet 的逻辑重新审视：

- 窗口是否应该固定尺寸
- 哪些区域应该允许拖拽
- 哪些面板应该悬浮
- 哪些功能应该展开而不是跳页
- 如何减少用户视线移动
- 如何让窗口与桌宠形成一个整体
- 如何处理屏幕边缘
- 如何处理不同分辨率
- 如何处理窗口空间不足
- 如何减少传统网页 Navigation 的存在感

目标是让用户感觉它是“住在桌面上的助手”，而不是“一个网页套了桌宠皮肤”。

5. 功能页面统一\
   检查当前项目全部界面，不要只优化首页。

包括：

- 桌宠主界面
- 聊天
- 聊天历史
- Todo
- 设置
- 状态显示
- 快捷操作
- 弹窗
- 二级页面
- 空状态
- 错误状态

建立统一 Design System，确保所有页面：

- 颜色一致
- 字体一致
- 间距一致
- 圆角一致
- 动画一致
- 控件一致
- 层级一致

避免每个页面像不同项目。

6. 响应式与布局稳定性\
   重点检查：

- 1080P
- 2K
- 高 DPI
- 系统缩放
- 小尺寸窗口
- 内容溢出
- 长文本
- 超长 Todo
- 长聊天内容
- 不同语言长度

不得通过大量绝对定位硬编码来实现视觉效果。

桌宠与窗口之间的连接效果必须能够适配窗口尺寸变化，而不是修改尺寸后必须重新绘制整套 SVG。

7. 工程质量\
   在视觉优化同时，对前端代码进行必要重构。

要求：

- 减少重复代码
- 拆分合理组件
- 提取 Design Token
- 提取动画参数
- 统一 spacing / radius / shadow / typography / z-index
- 避免 magic number
- 避免无意义 CSS 覆盖
- 避免过深组件嵌套
- 保持组件职责清晰
- 保持代码可维护性

如果当前架构存在明显问题，可以重构，但不要为了重构而重构。

8. 性能\
   重点检查：

- 首屏性能
- 动画性能
- SVG 性能
- DOM 数量
- 重渲染
- 图片加载
- 长列表
- 聊天记录
- 内存泄漏
- 事件监听
- 定时器

动画优先使用 transform / opacity 等高性能属性。

不要为了视觉效果明显降低性能。

9. 可访问性与交互细节\
   完善：

- 键盘操作
- Focus 状态
- Tab 顺序
- ESC 关闭
- Enter 提交
- Tooltip
- aria
- 对比度
- 点击区域
- 防误触
- 禁用状态

这些细节不能因为这是桌宠产品而被忽略。

10. 执行方式\
    不要只分析或给建议。

请直接检查当前代码库并开始修改。

执行流程：

第一步：\
完整审查当前项目的页面、组件、CSS、动画和交互逻辑。

第二步：\
识别当前体验中影响最大的设计和工程问题。

第三步：\
制定统一的视觉、交互和 Design System 规则。

第四步：\
直接修改代码完成优化。

第五步：\
检查所有主要页面和状态的一致性。

第六步：\
进行一次最终 UI / UX / Performance Review，并继续修复明显问题。

不要在完成一个页面后就停止。

11. 修改原则\
    必须遵守：

- 不破坏现有核心功能
- 不随意删除现有功能
- 不修改现有接口契约，除非确有必要
- 不为了视觉效果牺牲可用性
- 不为了重构而大规模改写稳定代码
- 不允许只修改颜色、阴影、圆角就宣称完成
- 不允许只给建议而不实际修改代码
- 不允许留下明显的 TODO 或半成品
- 修改后必须保证项目可以正常运行

如果某个实现存在多个方案，请主动选择你认为产品体验最好、工程质量最高的方案，不需要每一个小细节都询问我。

12. 最终验收标准\
    最终结果至少应该达到：

视觉上：\
像一个真正准备发布的成熟桌面宠物产品，而不是 Demo。

交互上：\
自然、丝滑、直觉化、有反馈。

桌宠融合：\
宠物和 UI 是一个整体，而不是两个独立元素。

工程上：\
结构清晰、样式统一、易于维护。

性能上：\
动画流畅，没有明显卡顿和无意义渲染。

细节上：\
即使仔细检查，也很难发现明显粗糙、临时、拼接或 Demo 感的地方。

请始终站在：\
「如果这是一个准备正式发布、长期维护并面向真实用户的商业桌宠产品，我们还可以把什么做到更好？」\
这个角度持续检查和改进。

在没有明显可以继续提升的问题之前，不要因为“功能已经可以使用”就停止优化。
