# 内部管理后台与服务端追踪设计

状态：方案已评审并完成首期实施。需求权威来源为 [prd.md](prd.md)，真实与隔离验证边界见 [verification.md](verification.md)。

实施备注：当前管理端是独立 React/Vite workspace，使用自定义轻量数据访问与 Lucide 图标，没有引入 Refine；服务端首期代码落在 `server/app/admin.py`、`server/app/model_config.py` 和现有 runtime/service 模块。下文保留规划中的完整边界与后续验收要求，未执行的真实环境检查不得按页面构建结果推断为已完成。

## 1. 架构与模块

新增独立 `admin/` React / TypeScript / Vite 应用，以 Refine Core 处理常规数据查询、认证接入、表单和路由；链路追踪页自行实现。通过同源 `/admin/v1` HTTP API 访问现有 FastAPI。沿用 psycopg、PostgreSQL 和 Redis，不重写 ORM，不引入第二业务服务或示例数据源。

服务端建议模块为 `app/admin/`（路由、认证、查询、开通、审计）、`app/model_config/`（版本、密钥、模型工厂）和 `app/tracing/`（采集、投影、清理）。目录名是实施方案，不表示目录已存在。

部署：反向代理服务管理静态文件并代理 API，桌面现有 `/v1` 保持独立鉴权。开发使用 Vite 代理，不放开设备 WebSocket 的 Origin 限制。只读取管理页面时不创建 Agent 任务、不调用模型。

首期维护一项整合任务，内部按可验证工作包顺序交付；不创建仅名义关联的父子任务。若实施需要拆任务，模型版本先于模型追踪，管理 API 先于前端联调，具体依赖必须保留。

## 2. 身份、权限与审计

- 新增 `admin_users`、`admin_sessions`、`admin_audit_events`；管理员不是 devices 的新增角色。初始管理员通过显式 CLI 建立，不预置默认密码或管理账号。
- 内部账号采用密码登录；使用成熟密码散列实现，数据库仅存散列。随机会话标识仅通过 HttpOnly、SameSite Cookie 传递，生产 HTTPS 设置 Secure；服务端存会话标识摘要、过期时间、管理员状态。
- 所有写接口校验 CSRF、会话、角色和 Origin；登录具备有界失败限流。退出/停用立即使会话失效。不得把 device bearer token 解释为管理员。
- 两固定角色：admin 与 observer。observer 仅查总览、运行元数据、工具定义、配置非敏感字段和健康；正文、待办标题、工具参数/结果单独鉴权，不靠前端隐藏。
- 审计记录操作者、动作、对象、结果、时间和请求标识；变更差异只保留非敏感字段。开通、撤销、配置发布、回滚必须与审计保持事务一致。正文读取先记录访问审计；审计失败则拒绝这次管理操作，不影响桌面 Agent 的业务执行。
- 设备开通复用从 CLI 提取的业务逻辑；幂等键防止重复创建。设备凭证仅签发响应一次返回，禁止缓存及持久浏览器存储；响应丢失后展示已创建的设备并允许撤销重发，不尝试恢复明文。

## 3. 模型配置版本与密钥

第一版仅支持当前运行链使用的 OpenAI 兼容协议，一套全局生效配置；编辑 base_url、model、API Key、timeout_seconds。worker 并发、工具步数、系统提示词和工具 schema 不在线编辑。

新增表（名称可在实施时统一，字段语义必须保持）：

| 表/字段 | 职责 |
|---|---|
| model_config_versions | 不可变配置快照、父版本、模型与地址、超时、secret_version_id、创建者与时间 |
| model_secret_versions | 加密密钥、加密算法版本、部署密钥标识；不保存可回显原文 |
| model_config_state | 全局 active_version_id 与 CAS revision；标识是否进入管理配置模式 |
| model_config_tests | 测试绑定的不可变版本、检测项、结果和脱敏错误；不保存 Key |
| model_config_publications | 每次发布/回滚的前后版本、操作者、时间与幂等键 |
| agent_runs.model_config_version_id | 接收任务时绑定的版本，可空以兼容历史行；管理模式的新任务必须有值 |

密钥使用成熟认证加密库，部署加密主密钥由环境/挂载 secret 提供，不能保存在同一数据库或前端。新 Key 使用 write-only 字段；未输入表示沿用指定旧 secret 引用，绝不提交遮罩字符串。服务仅展示 has_key/版本标识，日志和异常不串行化密钥对象。主密钥缺失时配置管理写入明确不可用；已启用管理模式后无法解密则拒绝新模型任务，不降级到其他模型。

### 配置操作流程

1. 保存：生成不可变草稿版本，字段校验完成，不改变生效配置、不调用模型。base_url 拒绝用户信息和凭证查询参数，生产远端用 HTTPS；私网模型地址由部署允许的端点范围约束。拒绝凭证重定向。
2. 测试：管理员显式触发真实流式请求，不包含业务会话、无工具、无待办写入；界面在按钮旁写明产生模型调用和用量。输出仅用于诊断；成功只证明该配置的基础模型流式响应，不证明业务工具兼容。测试另有诊断 ID，不能计入真实用户运行成功率。
3. 发布：要求该不可变版本有成功测试，校验密钥可用；以 expected_revision 在一个事务中切换 active 指针、递增 revision、记录发布和审计。失败/过期结果不复用到修改后的新版本。后台显示“已发布，供新请求使用”以及测试时间，不声称全部在途运行已切换。
4. 绑定：新任务接收事务读取并锁定当前 active 状态，写入 run 的版本；与发布建立明确先后顺序。相同 request_id 先走既有幂等检查，返回原 run，不重新选模型。排队任务也保持接收时版本。
5. 执行：worker 按 run 绑定版本取配置并创建/获取有界缓存的模型实例，同一 run 内后续模型调用不重新选 active。总超时与模型超时从该版本取值。服务端状态接口改查实际生效配置，避免继续报启动环境值。
6. 回滚：选历史非敏感配置重新生成候选版本；明确选择沿用当前 Key 或历史 Key，重新测试后发布，记录来源版本。不会撤销已发出的上游请求。替换应用 Key 不等于在模型提供方撤销旧 Key；已接收任务仍需旧 Key 完成，提供方提前撤销导致的失败应如实记录。

已有环境配置继续支持：尚未进入管理模式时保持既有行为。首次正式启用管理配置须显式执行迁移操作，并要求队列无 queued/running 任务；否则返回冲突，避免旧任务被静默换模型。迁移只将当前配置加密保存并建立基线，不输出 secret。未配置模型的服务可直接测试和发布首个有效版本。状态标记建立后，数据库版本是唯一权威；环境只提供基础设施和加密主密钥。重新启动不覆盖已发布配置。

## 4. 追踪数据与业务事件边界

用 run_id 作为稳定关联入口，新增 model_call_id 和 step_index，工具关联已有 tool_call_id；不假称现有 UUID 已符合 OTel trace ID 格式。若未来接入标准 OTel，另做上下文/ID 映射。

| 新增记录 | 核心内容 |
|---|---|
| run_trace_state | run/session/account、采集版本、预期/已采集步骤、缺口、完整性状态 |
| model_call_traces | run、step、配置版本、开始/结束、单调时钟耗时、第一块/首文本时间、状态、错误类型/HTTP 状态、provider request ID（存在时）、usage 与来源 |
| trace_payloads | 请求/响应脱敏快照、截断标识、原始字节数、正文到期时间 |
| tool_trace_links | model_call_id 与现有 tool_call_id、父子/步骤关系；不复制工具副作用或重写业务结果 |

采集位置以 `server/app/agent_service.py:250` 的 `_run_graph` 为主：每次 `model_node` 调用前捕获最终应用层 messages、工具目录与实际配置；遍历流时更新指标和有界响应缓冲，调用结束写最终结果；`tools_node` 将实际工具与触发它的模型调用关联。

请求快照明确标注 application_request，不称为完整上游 HTTP 报文。记录系统提示词、历史、当次用户消息和真实工具回传；若 SDK 添加默认字段，不把未知值显示成确认的上游生效参数。不额外记录协议未公开的内部推理；现有 `visible_text` 行为保持。

TTFT 仅在可识别到第一内容/工具生成块时计算；另存第一响应块与首段可见文本延迟，空元数据块不能冒充首 Token。使用单调时钟计算同进程耗时，绝对时间仅用于排列。提供方 usage 按最终累计口径记一次，不能把每块累计值相加；不返回 usage 时为 null+unavailable。缓存 Token 仅在实际返回时展示，不能推算。

运行/工具事件保持既有 seq 及副作用事务；追踪记录不插入客户端不认识的业务事件。运行根状态由业务表派生，工具结果以原表为权威。新增观测写入经有界队列和独立连接/事务，按调用生命周期批量更新；队列满/写失败时记录脱敏告警和可恢复的缺口，业务继续。永久丢失无法恢复时显示 incomplete，禁止伪造补全或重放模型。关闭时有界刷写，失败不阻塞退出。若数据库本身故障影响原业务，仍按原契约失败，不能承诺数据库故障下业务可用。

活跃阶段管理 API 返回已采集的状态/预览；部分输出标记 partial，结束后以持久结果为准。追踪刷新不触发模型调用。历史 run 无模型级记录时显示 legacy/uninstrumented，不倒推提示词、费用或完整步骤。

## 5. 管理 API 与页面契约

| API 组（`/admin/v1` 前缀） | 方法和职责 |
|---|---|
| auth | POST login/logout，GET me；受限正文读取 POST + CSRF，不允许浏览器预取触发正文审计 |
| accounts/devices | GET 列表/详情；POST 创建与 revoke；正文和凭证响应 no-store |
| overview/health | GET 统计与依赖；明确时间窗口、分母和数据来源 |
| sessions/runs | GET 分页与筛选、run 详情、trace 元数据；POST 受控读取单条 payload |
| todos/tools | GET 元数据和工具目录；POST 获取有权限的待办正文 |
| model-config | GET 版本/状态；POST 启用管理配置、保存版本、测试、发布及回滚；CAS 冲突 409 |
| audits | GET 受控分页审计，observer 不读取审计中的人员关联信息 |

列表统一 `items,next_cursor`，有稳定次序与服务端上限；筛选/排序字段白名单。管理端错误返回稳定 code、message、request_id，不泄漏提供方原始异常体。列表不得将失败转换为成功空数组。

页面导航：总览、账号与设备、会话与运行（内含链路追踪）、模型配置、待办与提醒、工具目录、系统与审计。基于 Lucide 和现有字体/视觉要求设计，追踪画布可定制，但表格、过滤、键盘操作与文字可读性优先保证。

追踪详情：顶部状态/耗时/调用数/用量；时间概览与记录表联动；检查器查看某步输入输出/配置/错误。长列表分页+虚拟化；默认跟随最新，用户上翻暂停，显式按钮恢复跟随。轮询建议 1 秒且同一查询不重叠；隐藏页暂停，退避重试，不依赖设备 WS；刷新保留 run 与选中记录 URL。

## 6. 保存与清理

按 PRD 建议只清理新增表：正文 30 天、追踪元数据与审计 90 天，均按终态/记录时间分批；活跃任务不清理。分别记录正文已过期状态，先清正文后清元数据。检查器对已过期追踪正文不从业务消息表重新拼装，不能绕过追踪保存期限；显式会话业务查询仍受独立权限和现有数据策略约束。

单条请求/响应正文建议最多 256 KiB（UTF-8），截断注明位置与原始大小，先按已知凭证与敏感字段脱敏再保存，常规模型参数按白名单保存。正文不进入普通访问日志或审计。保留期限通过部署配置调整，缩短期限不立刻同步批量删除，按已声明清理任务运行并记录策略版本。存量业务表不做删除迁移。

## 7. 兼容、上线和回退

迁移仅增表/可空字段/索引；不改现有角色约束、设备协议或业务状态。现有未提交桌宠 UI 改动不纳入本任务；实施前在明确归属的分支/隔离目录落地，禁止为清洁状态 reset/stash 他人改动。

先部署兼容环境模式的服务和新迁移，再开管理入口，最后显式启用数据库配置。支持管理配置的版本是启用后的回退下限；回退前端或关闭后台不改变 active 配置。不可直接回退到只读环境变量的旧服务并声称等价，应先完成显式配置迁移/排空队列并验证。密钥备份与数据库备份必须分别具备恢复路径。

无新增付费网关、Langfuse 或云遥测依赖；不向外部自动导出追踪。尚未进行真实部署、模型测试、数据库迁移或浏览器验收。
