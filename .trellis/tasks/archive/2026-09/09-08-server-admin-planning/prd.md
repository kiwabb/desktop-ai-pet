## 已确认的项目事实

- 前端 React 19 / TypeScript / Vite；服务端 FastAPI，使用 psycopg 直接访问 PostgreSQL，Redis 保存节点租约。证据：`package.json`、`server/app/db.py:9`、`server/app/coordination.py:37`。
- 账号创建、设备凭证发放及撤销目前通过 CLI；设备角色只有 control/node，没有管理员身份。证据：`server/app/cli.py:24`、`server/migrations/001_core.sql:5`。
- 已保存会话、运行、消息、工具调用、待办和有序事件。证据：`server/migrations/002_runtime.sql:1`；提醒字段见 `server/migrations/004_todo_reminders.sql`。
- 当前 HTTP 接口按设备所属账号访问，没有管理查询路由；已有 WebSocket 拒绝浏览器 Origin。证据：`server/app/main.py:55`、`:85`、`:129`。
- 模型配置来自环境变量，在服务启动时创建模型实例；现有迁移与运行存储未持久化 Token 用量及计费记录。证据：`server/app/config.py:8`、`server/app/agent_service.py:135`、`server/migrations/002_runtime.sql:9`。
- 单机模式直连模型并使用客户端 SQLite，服务端模式才访问 Python 服务。证据：`.trellis/spec/desktop/dual-mode-llm.md:8`。

## 首期需求与后续范围

用户明确确认的定位及能力见状态与目标；以下细化规则作为本次完整评审方案，不追溯为此前已经批准的决定。

| 编号 | 阶段 | 功能与用户可见行为 |
|---|---|---|
| R1 | 首期 | 管理员登录、退出、会话过期；独立管理身份，设备 token 不能访问管理入口。首期角色建议为管理员与只读观察者。 |
| R2 | 首期 | 账号列表、账号创建、设备列表、设备凭证发放及撤销；凭证仅签发时展示/下载，不提供历史明文查询。 |
| R3 | 首期 | 总览展示真实账号数、有效设备数、有效节点租约数、按时间窗口统计的运行状态和失败率；Redis 故障显示状态未知，不能当作全部离线。 |
| R4 | 首期 | 会话与运行中心：按账号、时间、状态筛选和分页，从运行进入 R10 链路追踪详情。敏感正文查看受权限控制并记审计。 |
| R5 | 首期 | 待办与提醒只读查询，关联来源工具调用和运行；工具目录只读展示实际注册项、版本、参数定义和执行位置。 |
| R6 | 首期 | 系统状态页显示数据库、Redis、模型配置状态及可公开的生效参数；管理写操作和敏感数据查看留下审计记录。 |
| R7 | 首期，用户已要求 | 编辑 OpenAI 兼容模型的服务地址、模型名称、API Key 和超时；保存草稿、显式连接测试、发布、历史版本和回滚。全局单一生效版本；发布后新接收请求使用新版本，已接收及执行中的任务固定原版本。密钥仅可替换，不回显原文。测试产生真实模型调用且标明结果覆盖范围；仅保存和浏览不调用模型。 |
| R8 | 后续 | 在 R10 的真实 Token 采集基础上增加成本估算、账号配额与限流、多模型路由；费用注明价格版本与计量来源，缺少 usage 时不显示零成本。 |
| R9 | 后续 | 桌宠角色/资源版本与发布渠道管理；只有进入素材分发和客户端更新阶段才纳入，不因桌宠名称自动扩展为商城。 |
| R10 | 首期，用户已要求 | 参考 DeepSeek Harness Trajectory：按会话、运行/轮次、模型步骤和工具调用展示记录；时间概览与记录列表联动，点击进入输入输出检查器；显示真实模型请求上下文、生效模型/参数、工具目录、工具参数/结果、开始结束时间、首 Token 延迟、Token 用量和失败位置。流式更新不抢走历史阅读位置，刷新恢复已持久记录。缺失数据和运行中状态明确标注。 |

## 内部管理操作边界

| 操作 | 管理员 | 只读观察者 |
|---|---|---|
| 查看总览、依赖状态、工具目录、运行元数据 | 允许 | 允许 |
| 创建业务账号、发放或撤销设备凭证 | 允许，记录审计 | 禁止 |
| 查看会话正文、请求上下文、工具参数与结果、待办内容 | 允许，受控查看并记录审计 | 默认禁止，仅查看元数据 |
| 修改业务待办、删除会话、重放失败运行 | 首期不提供 | 禁止 |
| 查看模型名称与非敏感生效参数 | 允许 | 允许 |
| 修改模型配置、测试、发布或回滚 | 允许，记录审计 | 禁止 |

管理员身份与业务账号区分；内部成员不通过公开注册获取管理权限。只读观察者的“只读”不自动赋予所有私人正文访问权。上述角色与权限是候选方案，不代表用户已逐项批准。

## 追踪数据保存建议

新增追踪请求/响应正文保留 30 天；新增追踪元数据及管理审计保留 90 天。清理仅针对新增追踪表和审计表，不删除既有会话、消息、待办及业务事件。检查器清楚区分未采集、脱敏、截断、过期和故障丢失；到期前不以空字符串冒充完整记录。密钥和凭证不进入追踪；首期不提供正文批量导出。部署配置可调整期限，缩短期限需明确告知影响。本方案等待整体评审通过后实施。

## 候选验收标准

- AC1（R1）：管理员能登录和退出；未登录、过期会话、设备 token、只读角色写请求均被服务端拒绝。
- AC2（R2）：创建真实账号并发放设备凭证后，桌面端以该凭证接入；撤销后新请求被拒绝、现有连接按既有契约失效；刷新后台仍显示撤销状态。
- AC3（R3/R4）：统计与筛选结果对应真实数据库记录；可从已有失败运行追溯到事件和已提交工具结果；刷新后仍可定位同一运行。无数据时展示真实空态。
- AC4（R5）：后台待办状态与所属账号的服务端列表一致；到期时间不标记为已送达，因为现有系统没有通知送达回执。
- AC5（R6）：依赖故障和未配置模型各有独立状态；写操作及敏感正文访问可追溯操作者、目标、结果和时间，不记录密钥。
- AC6（已确认边界）：只采集和展示服务端链路，不新增单机模式采集或客户端本地会话上传；服务端运行完成不标记为客户端已收到或已展示。浏览器管理链路不通过放开现有设备 WebSocket 的 Origin 限制实现。
- AC7（R10）：实际运行发生“模型调用 → 工具调用 → 再次模型调用”时，按真实顺序展示各步骤、关联关系及各自结果；没有执行的步骤不生成占位成功记录。运行失败后保留已提交的工具事实。
- AC8（R10）：检查器展示当次捕获的上下文与参数，注明采集层级及脱敏/截断，不以当前配置回推历史请求；每个模型步骤单独展示用量，提供方未返回时显示未采集。TTFT 的采集起止点固定，并与首段可见文本延迟区分。
- AC9（R10）：时间区间选择可定位对应记录，选择记录可定位对应时间；浏览历史时流式新增不强制跳底；刷新恢复、前翻分页不重复记录；历史缺少模型级埋点时显示追踪不完整。
- AC10（R10）：追踪 UI 与可选外部遥测故障不改变业务执行结果、不触发模型或工具重放；链路缺口可辨认，不把导出交接成功描述为送达成功。
- AC11（R7）：管理员保存草稿后，旧配置仍生效；显式测试执行真实、无业务工具的流式模型请求，显示测试版本、时间、响应及脱敏错误。模型列表查询或配置存在不等同于测试通过。
- AC12（R7/R10）：配置 A 的已接收任务在发布 B 后仍全程使用 A；发布后的新请求使用 B，重复提交同一 request_id 不换版本；后台详情与真实调用记录一致。并发发布冲突明确拒绝，刷新后和服务重启后保持同一生效版本。
- AC13（R7）：回滚产生新的发布记录，并只影响后续新请求；密钥不可解密或目标不可用时不冒充生效成功，不静默切回环境变量；API、日志、审计、追踪及浏览器持久存储均不暴露原始 Key。
- AC14（数据保存）：新追踪正文和元数据按声明期限分别到期，检查器显示到期状态；既有业务记录不被清理；只读角色不能通过正文接口绕过权限。

以上是实施验收目标。本次已完成静态和隔离验证，未执行真实运行验收，也未创建账号、设备或业务样例数据。
