# 实施计划与验收

状态：已实施（2026-09-08）。关联 [PRD](prd.md)、[设计](design.md) 与 [验证记录](verification.md)。

本次实际落地了首期垂直切片：独立 `admin/` 管理端、管理身份与审计、设备发放/撤销、模型配置版本/加密/测试/发布/回滚、运行模型调用追踪和受权限控制的正文读取。规划中的 Refine 依赖没有引入，管理端使用项目已存在的 React/Vite/Lucide 工具链；服务端实现当前落在 `app/admin.py` 与 `app/model_config.py`，没有拆成规划中的多目录包。

## 顺序和依赖

1. **工作区与依赖准备**：已确认 task 状态、分支、未提交文件归属和可用端口；本任务未纳入桌宠动效改动。管理端已纳入根目录 pnpm workspace，锁定 React/Vite/Lucide 依赖并通过 frozen lockfile 检查；服务端使用 `scrypt` 与 Fernet。
2. **管理认证与模型版本基础**：增量迁移、admin 身份/会话/CSRF/审计、CLI 初始管理员、版本与 secret 存储、全局 CAS 指针；保留环境模式。依赖步骤 1。
3. **配置真实生效链路**：草稿/显式测试/发布/回滚 API；启用迁移的队列检查；run 在接收时绑定版本，worker 每 run 使用固定模型工厂，状态 API 查有效配置。依赖步骤 2；先完成此步再增加追踪的配置关联。
4. **服务端追踪采集**：模型调用开始/流式/终态埋点，工具关联、快照脱敏、usage、时间指标、有界写入与缺口、保存期清理。依赖步骤 3。不得破坏业务事件 seq、工具事务与停机恢复。
5. **管理查询与开通 API**：分页筛选、总览、账号设备发放撤销、运行/追踪查询、正文权限、待办与工具目录、审计查询。认证依赖步骤 2；追踪 API 依赖步骤 4。
6. **管理前端**：独立 admin 应用、登录与导航；常规列表/表单；配置保存测试发布回滚；Trajectory 时间概览、记录表、检查器、跟随/暂停/分页/刷新。依赖步骤 3–5 的稳定接口。先完成完整路径，再统一视觉与动效。
7. **整合验收**：trellis-check 检查真实契约与风险测试；真实服务/模型/浏览器验证分层记录。失败修复后只重复受影响检查。
8. **交付**：已同步 server README、后台启动部署说明、模型配置与追踪规范；已完成静态和隔离验证。真实 PostgreSQL、模型、浏览器和桌面链路仍按 [验证记录](verification.md) 标明为未运行；提交与任务归档在质量门禁通过后完成。

每个工作包可独立验证，但最终交付是“认证 → 设备接入 → 真运行追踪 → 配置切换 → 新旧任务版本核验”的整合闭环，不按页面数量报告完成。

## 重点风险与检查

| 风险 | 必须检查的行为 |
|---|---|
| 管理/设备鉴权混用 | 设备 token 无法访问 admin；过期、退出、停用即时失效；observer 无正文/写权限 |
| 重复提交与并发发布 | 原 request_id 保留原配置；CAS 仅一方生效；绑定版本与发布有明确事务顺序 |
| 密钥/环境迁移 | 新版本不覆盖已接收 run；缺加密主密钥不回退其他配置；启用时队列非空拒绝 |
| 追踪改变业务 | 写入队列满、观测事务失败不撤销工具结果、不重放；原业务 DB 故障仍正常报错 |
| 采集失真 | usage 无来源为 null、累计 chunk 不重复累加；TTFT 排除空块；历史记录注明不完整 |
| 隐私和清理 | Key 无泄漏；正文截断/到期可见；只清新增表，不删除原会话待办；普通列表不夹带正文 |
| 页面完成假象 | 实际发送产生运行、真实流式进度、选择工具可查结果、刷新/翻页可恢复、错误可见 |

## 验证命令与范围

实施后从 `server/` 执行 `uv run python -m unittest discover -s tests`；覆盖认证、配置 CAS/绑定、原 gateway/runtime/todo 行为。新增的隔离模型与数据库测试必须显式标记 mock，不作为真实调用验收。

配置切换、run 幂等、迁移与追踪写入涉及事务，必须补真实 PostgreSQL 的针对性集成检查。临时数据库或业务样例仅在用户另行明确授权后创建；当前不创建。共享真实库只执行已获授权的变更，验收优先使用现有记录与真实只读查询。

在 `admin/` 定义并执行 `pnpm exec tsc --noEmit` 与 `pnpm build`，测试脚本按落地工具链命名；检查有业务意义的权限/轮询/分页/配置冲突行为，避免只镜像实现的测试。独立后台改动不要求重新构建 Tauri；如修改客户端契约，先重新评审范围。

文档阶段仅检查改动文本、相对链接、JSONL 有效性与 diff，不运行上述构建或测试。

## 真实验收清单

- [ ] AC1/AC14：管理员与观察者实际登录验证，拒绝未授权接口和正文读取。
- [ ] AC2：获准的真实账号/设备发放 → 桌面接入 → 撤销 → 新请求及存量连接拒绝；凭证不进日志。
- [ ] AC3–AC10：真实服务端只读待办查询触发实际模型和 todo_list，再次模型调用完成；逐步骤可见、计量有来源；空业务库保持空态。真实提供方没有 usage 就记录该限制，不补造 Token。
- [ ] AC11：保存草稿不改变 active；真实显式测试成功/失败状态可见，测试未写待办且与业务统计隔离。
- [ ] AC12：用用户已有可用配置/密钥验证 A/B 发布，新请求用 B、已接收任务用 A；若没有第二个可用配置，只能报告真实切换链路未验证，不能用 mock 冒充。
- [ ] AC13：真实回滚、服务重启与页面刷新后 active 一致；上游提供方 Key 撤销不在本任务自动执行范围内。
- [ ] AC9：查看历史时不抢滚动；分页、失败重试、刷新恢复、响应式布局和键盘检查完成。
- [ ] AC14：清理与泄漏规则通过隔离测试；真实数据不因验收缩短保存期或人为改时间。

真实模型调用/真实设备创建的验证需在实际环境和用户授权范围内进行；无可用凭证时继续完成可验证工作并明确记录缺口，不创建第二个演示服务或默认账号。
