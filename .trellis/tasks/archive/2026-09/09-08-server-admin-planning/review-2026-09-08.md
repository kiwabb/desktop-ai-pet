## P1：应先修复的阻断问题

### F1. 新运行绑定使用非法外连接加锁 SQL

- 位置：`server/app/model_config.py:68`、`:74`、`:265`，`server/app/runtime_store.py:147`。
- `LEFT JOIN model_config_versions` 后追加不带 `OF s` 的 `FOR UPDATE`，PostgreSQL 拒绝锁定可空连接侧。
- 新 run 无条件调用 bind_for_new_run，即使 management_enabled=false 也先执行错误查询。部署迁移并加载新代码后，原环境模式的新消息、管理启用及发布均会受影响。
- 实际只读等价复现：`EXPLAIN SELECT c.oid,n.oid FROM pg_class c LEFT JOIN pg_namespace n ON n.oid=c.relnamespace WHERE c.oid=0 FOR UPDATE` → `0A000 FOR UPDATE cannot be applied to the nullable side of an outer join`；改为 `FOR UPDATE OF c` 后通过。
- 修复方向：仅锁定状态主表并验证与接收/发布事务顺序；补 PostgreSQL 集成测试。

### F2. 模型配置审计 INSERT 占位符数量错误

- 位置：`server/app/model_config.py:117`。
- 指定 8 个插入列，VALUES 包含 8 个占位符和一个固定字符串，共 9 个值；实参只有 7 项。
- _audit 调用无法执行，导致保存草稿、管理启用、测试完成、发布与回滚候选创建事务失败。
- 修复方向：校正列/值/参数映射，并验证实际写入事务。只测 public_version 无法发现此问题。

### F3. 连接测试的审计状态违反数据库约束

- 位置：`server/app/model_config.py:220`、`:221`；`server/migrations/005_admin_model_trace.sql:28`。
- 测试状态是 succeeded/failed，审计只允许 success/failure。修复 F2 后仍会 CHECK 失败，测试终态更新回滚，已保存测试停在 running。
- 修复方向：显式映射测试域和审计域状态，分别验证模型成功与失败分支。

### F4. 观测写入会占用并耗尽业务超时

- 位置：`server/app/agent_service.py:315`、`:332`、`:388`；`server/app/runtime_store.py:182`、`:199`。
- 模型开始/结束和工具关联都直接 await 追踪 SQL，没有独立写超时或有界异步队列。仅追踪表发生锁等待，就能阻断模型/后续工具并触发任务总超时。
- 快速异常被捕获不代表挂起写入隔离，违反 AC10。需实现独立、有界观测路径，并把丢失记录标成缺口。

## P2：追踪与配置正确性

### F5. 超时取消后模型步骤永久 running

- 位置：`server/app/agent_service.py:359`、`:260`；`server/app/runtime_store.py:235`。
- 流循环只捕获 Exception，CancelledError 由外层取消时没有调用 finish_trace；业务 run 已 failed/interrupted，trace 的 ended_at 仍空。清理又仅选 ended_at 非空行，该类元数据无法按期清理。
- 隔离内存探针：模型输出一个 chunk 后挂起，总超时 0.05 秒；观察到 run=failed、业务 delta=1、finish_model_trace.await_count=0。不是实际提供方验收。

### F6. 成功步骤覆盖既有追踪缺口

- 位置：`server/app/runtime_store.py:209`。
- 每次模型成功就把整个 run 的 integrity 设为 complete，覆盖此前工具关联或终态写入失败的 incomplete，且 gap_reason 保留；第一个模型完成也不等于整个运行追踪完成。
- 应让缺口持续有效，在 run 终态按预期步骤/实际记录汇总完整性。

### F7. 请求快照缺工具协议，无法还原模型实际输入

- 位置：`server/app/agent_service.py:334`、`:373`。
- 所有消息都裁为 role/content，缺 AI tool_calls 的 ID/参数，以及 ToolMessage 的 tool_call_id/name/status；输出只保留工具名。
- 第二次模型调用的关键因果信息丢失。隔离探针实际确认快照 AI/Tool 字段只有 role/content。应以受控序列化保存应用层完整消息协议，注明脱敏/截断。

### F8. 自定义模型端点未启用 streaming usage 请求

- 位置：`server/app/agent_service.py:291`、`:372`，启动模型构造同类问题。
- 当前 SDK 自定义 base_url 的 `_should_stream_usage()` 为 False，代码未显式请求 stream_usage；仅末尾读取 usage_metadata 不能要求提供方返回 Token。
- 应请求支持的用量协议并正确处理不支持的提供方；不能把缺失值当零，也不能把缺失全部归咎于提供方。

### F9. 模型配置超时没有应用到任务总超时

- 位置：`server/app/agent_service.py:253`、`:293`。
- SDK 超时取版本值，任务总超时仍取环境值。后台发布 180/300 秒、环境 90 秒时运行仍在约 90 秒终止。应在执行入口统一解析 run 绑定的配置。

### F10. 模型测试任意非空字节即通过，且发布不再验证 Key

- 位置：`server/app/model_config.py:205`、`:209`、`:234`。
- 测试只拒绝 HTTP>=400，302 HTML、200 错误页、SSE error 都可被标成功；首块后提前结束，也没有验证完整协议结果。修复审计阻断后，无效端点会取得发布资格。
- 发布仅检查历史任意成功测试，不确认当前主密钥可解密该 secret；测试后更换主密钥可发布不可用配置。应校验当前 secret 与有效测试，明确结果覆盖范围。

### F11. 追踪正文没有脱敏，流中失败丢失部分输出

- 位置：`server/app/runtime_store.py:170`；`server/app/agent_service.py:349`、`:360`。
- _trace_body 只 JSON 序列化和截断。配置 Key 没有直接塞入快照，但用户/工具正文中的凭证会原样另存追踪，未实现承诺的脱敏。
- 流中只写业务 delta，追踪无 partial 进度持久化；普通失败结束时只存错误，已生成文本和首响应指标不保留。
