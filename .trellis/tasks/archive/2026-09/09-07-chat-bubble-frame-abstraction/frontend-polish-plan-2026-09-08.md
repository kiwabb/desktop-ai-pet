## 1. 目标

把现有白猫桌宠统一成一套精致、自然、稳定的桌面体验：收起时安静陪伴，展开时信息清晰，聊天、设置、待办切换连贯。用完整界面和真实交互判断完成度，不再通过逐个移动控件来修补整体比例。

“最好看”采用两层验收：用户确认最终视觉方向；所有布局、状态、原生交互和真实性检查满足下述标准。不会把主观审美或构建成功描述成“已经完美”。

## 4. 推荐视觉方向

### 温暖、克制的桌面伴侣

- **色彩**：奶油白作为主表面，暖深棕负责正文，暖橘用于主要操作；绿色/红色仅表达真实成功与错误。避免各页使用不同色块体系。
- **材质**：保留参考外壳的温暖边缘，内部采用细描边、浅阴影和少量内高光。白猫仍是视觉中心，不再叠加大面积玻璃、发光或持续闪烁效果。
- **字体**：沿用适合中文的系统字体；建立标题、正文、辅助信息三级样式。正文优先14–15px、辅助信息12px，必要的紧凑元信息单独校验可读性。
- **布局**：使用统一间距档位和内容边线。聊天重阅读，设置重字段与状态，待办重事项与操作；各页保持共同的标题、边框与滚动规则。
- **图标**：统一现有 Lucide 的尺寸、线宽、对齐与点击区域，不使用表情符号充当控件图标。
- **装饰**：猫爪与小脚印保留，但不能挡住输入、按钮、滚动内容或关键状态。优先调整内容与装饰的关系，不删除已经确认的参考元素。

先输出同一比例的全景对照图，覆盖收起、紧凑、展开聊天、设置、待办和提醒。使用真实空状态或真实运行状态；任何纯设计示意明确标为设计，不伪造聊天、工具或连接结果。

### 本计划建议一并确认的交互取舍

- 二级页面的“返回”统一用返回图标，回到进入前的聊天形态；保存成功仍遵守当前原生保存/返回契约。
- 暂未开放的附件、语音入口建议从主要输入区隐藏，避免让用户面对无效操作；本轮不实现这些功能，也不增加替代容器。
- 展开聊天增加常见 Markdown/代码块的安全排版与复制能力；不执行原始 HTML/脚本，不改变消息数据。依赖选型留在实施前的技术审查中。
- 上翻历史时停止强制跟随，回到底部后再跟随；有新内容时给出明确的回到最新入口。
- 在线/断线/模型未配置统一使用真实状态。静态状态装饰的处理先做局部设计对照，保持猫本体像素与原图文件不变，不用第二只猫或错误“在线”文案遮盖问题。

## 5. 分阶段执行

### 第一阶段：锁定全局设计与完整状态

1. 记录当前版本、角色资源校验值、各窗口尺寸和已确认的猫爪参数。
2. 整理颜色、字号、字重、边距、圆角、描边、阴影、图标和动效规范。
3. 将六个视图放在同一套视觉对照中，检查正常/空/加载/错误/禁用状态。
4. 先确认一版完整方向，再进入批量实现；不边写代码边更换风格。
5. 校正历史验收说明，明确现有真实配置、当前发送收起契约及最终包需要重验的项目。

**产出**：设计规范、六视图对照、状态清单、逐项差异说明。

### 第二阶段：统一公共组件与页面内容

1. 由 `ChatBubbleFrame` 管标题栏、外壳、插槽与装饰；宿主管桌面坐标和窗口层级。
2. 将重复颜色、边框、焦点和按钮状态收敛成有限的公共变量/规则，不扩大为无实际消费者的组件库。
3. 完善紧凑聊天的输入、快捷入口、可用/禁用与错误状态。
4. 统一展开聊天的消息排版、时间信息、长内容换行、工具结果和空状态，使阅读优先于装饰。
5. 统一设置四卡、待办列表、提醒区域的视觉语言，保留各自业务逻辑。
6. 清理被替代的样式之前，先确认所有消费者；不顺手删除其他任务代码。

**产出**：一套风格下的全部现有视图，及布局/样式归属说明。

### 第三阶段：打磨桌宠动作与原生连续性

1. 梳理白猫点击、拖动、右键、气泡展开/收起、设置/待办往返的完整状态转换。
2. 校验点击与拖动的区分，防止松手误开窗、拖动误发送、透明区域拦截桌面操作。
3. 优先补中文输入法保护：确认候选词不会提交消息，组合结束后 Enter 才发送，Shift+Enter 换行。
4. 保持猫、坐垫与底盘的视觉锚点，检查切换过程中的拉伸、闪白、残影和突跳。
5. 动效只表达状态：轻微待机、聚焦反馈、等待与说话反馈；不改角色原图，不增加持续干扰。
6. 建议微交互150–200ms、展开180–240ms、收起140–180ms；根据 WKWebView 实测校准，不用延时掩盖窗口时序错误。
7. 减少动态效果时取消非必要位移/缩放，保留清晰的即时状态变化。

**产出**：真实应用的连续操作录像，以及输入/拖动/窗口时序问题清单和修复证据。

### 第四阶段：真实聊天与任务状态收尾

1. 按当前 `ChatPanel.tsx:170` 的行为，验证紧凑发送被接受后的展开、真实回复可见、展开消息展示及输入草稿恢复；不沿用旧文档中“接受后收起”的过期描述。
2. 验证真实流式文本、工具活动、失败信息、断线恢复和历史恢复，防止漏消息、重复展示或自动滚动打断阅读。
3. 验证设置输入在状态刷新时不被覆盖，错误可以定位，保存行为与当前原生契约一致。
4. 使用已有真实待办/提醒验证列表、状态与空间分配；无数据时保留真实空态，不创建数据填充效果图。
5. 真实服务不可用时，仅完成当前可验证部分并列明缺口，不用演示适配器替代。

**产出**：按数据来源分类的验收记录。需要改变真实设置或待办数据的测试先列明具体操作和影响，不把视觉优化当成任意业务写入授权。

### 第五阶段：整体验收与本地交付

1. 在亮色、深色及复杂壁纸上对照完整桌宠；检查透明边缘、阴影、文字与脚印。
2. 覆盖紧凑、展开、独立窗口及较窄内容容器，检查多行标题、长地址/模型名和大段错误。
3. 检查键盘焦点、Escape、隐藏 inert、重新打开的输入焦点和减少动态效果。
4. 实测当前设备性能：目标交互流畅，动画以60fps为目标；记录帧耗时和空闲资源占用，不提前宣称达标。
5. 按修改范围执行专项检查；成组完成代码后运行一次前端构建，原生代码变化才增加相应 Rust 检查。
6. 生成本地应用包，核对加载的是该包的最新资源，记录回退提交。最后再展示完整效果和剩余限制。

**产出**：最终截图/录像、通过/未通过/未验证矩阵、本地安装包和回退点。

## 6. 验收底线

| 维度 | 通过标准 |
| --- | --- |
| 风格完整 | 六个视图使用同一字体、色彩、边框、阴影和交互规范；最终全景由用户确认 |
| 角色稳定 | 原图资源不变，无重影/双底盘；猫爪原参数保持，脚印完整可见 |
| 排版 | 标题、输入、按钮与装饰不相互遮挡；长内容可读，必要内容可滚动到达 |
| 可用性 | 焦点可见，文字对比度通常≥4.5:1；禁用/等待/错误有明确区别 |
| 输入与阅读 | 中文选词不误发；上翻历史不被流式刷新拉回底部；二级页面返回形态符合计划 |
| 原生交互 | 至少连续10轮打开→输入→切页→返回→关闭/重开，无卡死、闪白、错误焦点或明显位置跳变 |
| 真实数据 | 每项结果标记为源码/浏览器/原生/真实服务证据，绝不互相替代 |
| 聊天可靠性 | 真实发送、流式、工具、错误恢复与历史展示逐项验证；未验证项保持未通过状态 |
| 发布闭环 | 实际加载最新本地包，记录版本/提交和回退方式；不自动发布远端 |

## 7. 实施边界与优先级

- **P0**：整体设计方向、角色与几何约束、原生点击/窗口连续性、真实发送可见性、凭证与状态正确性。
- **P1**：六视图样式统一、长内容/窄布局、焦点与对比度、待办/提醒协调、细节动效。
- **P2**：性能微调、更多设备/显示器覆盖、轻微光影和动画节奏校准。
- 本次不新增主题商店、换装、小游戏、语音、附件、模型选择器、新提醒渠道或假测试连接。
- 不重构智能体服务，不改业务协议，不用新库或新资源替换已确认角色。修复原生交互确需底层改动时，以可复现问题为边界另列具体文件。
