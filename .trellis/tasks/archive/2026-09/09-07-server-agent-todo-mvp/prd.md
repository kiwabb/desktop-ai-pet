# 桌面智能体架构方向与最小待办闭环

## Goal

将逐项确认的架构方向保存到项目中，随后交付一个可从现有桌宠聊天入口使用的服务端智能体：通过自然语言创建和查询真实待办，重连后仍能读取已保存内容。

状态：三个子任务代码已落地；真实只读服务查询与桌面结果展示通过，创建与查询流程已由用户手动验收通过，完整桌面恢复仍待验收。

## Confirmed Facts

- 用户要求逐项确认技术和架构，习惯学习与主动提醒的业务细则以后讨论。
- 已确认的技术方向统一记录在[架构方向](../../../docs/SERVER_AGENT_ARCHITECTURE.md)。本任务不重新选择技术栈。
- 实施前前端在 `src/App.tsx:331` 拼接历史并发送请求；会话仅存于 `src/App.tsx:32` 的组件状态。
- 实施前 `src-tauri/src/lib.rs:743` 直接调用模型；`src/lib/ai.ts:15` 的请求只包含请求 ID 与消息数组。
- 实施前设置入口位于 `src/components/ChatPanel.tsx:41`，内容为模型服务配置，尚无远程助手服务设置。
- 已存在其他进行中的气泡框任务。本任务保留已确认的宠物形象、布局、收起/展开和跨桌面窗口行为。

## Requirements

- R1：持久记录全部已确认架构决策、现状、最小交付边界与后续方向。
- R2：桌面应用能够配置并连接独立部署的助手服务，显示真实连接/认证错误。用户电脑运行桌面客户端，无需启动 Python 智能体。
- R3：沿现有聊天入口发送用户消息，展示真实流式回复、工具执行状态与明确的成功/失败结果。收起窗口不取消已接受的任务。
- R4：智能体提供创建待办、查询待办两项真实能力。记录归属于账号；只有保存成功才可回复“已记录”。无数据时显示真实空结果。
- R5：任务接受后持久保存；重复提交同一请求不得重复创建待办。断线/重连后可以读取同一会话和任务状态，服务重启后已完成的待办仍可查询。
- R6：设备有独立身份，绑定到账号。注册中心管理工具定义和执行实例；设备只能登记已允许的能力。最小版本实际注册服务端待办工具，设备不声明尚未实现的电脑操作。
- R7：密钥与设备凭证不出现在浏览器存储、URL 查询参数或日志中。模型凭证只配置在服务端；现有本机模型密钥不自动上传或迁移。
- R8：验收报告区分静态检查、隔离自动化测试、真实服务运行和真实桌面端到端证据；不得为了展示完整效果创建演示待办或假模型回复。

## Proposed MVP Boundary

- 账号及设备凭证先通过服务端管理命令配置，保留账号归属和撤销能力；完整注册/登录/设备管理界面后续实施。
- 待办只包含标题、状态与创建时间；本轮提供创建、查询。完成、修改、删除、截止时间、提醒时间后续单独设计。
- 使用现有聊天与设置入口承载最小交互；不新增待办看板或另一套聊天窗口。
- 首次进入服务端模式使用新的服务端会话。旧的内存聊天不自动导入；保留原模型配置文件以便回滚。
- 会话只保留一个当前会话入口；服务端按账号和会话隔离。并发模型任务之间状态独立，同一会话的变更串行处理。
