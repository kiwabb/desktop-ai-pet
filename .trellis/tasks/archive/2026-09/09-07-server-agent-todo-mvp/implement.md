## 交付边界

目标为：现有桌面聊天 → 独立 Python 服务 → 真实模型调用待办工具 → PostgreSQL 记录 → 查询与重连恢复。

设备身份/注册、Redis 协调与持久任务是这个闭环的基础；电脑自动化和主动提醒算法只保留接口边界。

## 实现与检查分工

原生 Trellis 子代理仅在 task.py start 后派发，提示词以实际 Active task 路径开头，并声明共享工作区、禁止覆盖他人改动。

1. 实现代理先拥有 server/，主代理负责规划、合同决策和集成协调。
2. 合同稳定后，客户端实现代理拥有 src-tauri/、src/lib/agent.ts 和必要的 App/ChatPanel 集成；与服务端代理通过合同协作，避免同时修改同一文件。
3. 检查代理在实现完成后验证全链路，修复必须与文件所有者协调。
4. 不因派发代理而改变未获批准的产品范围。

## 拟执行命令

路径在阶段 1 建立后才有效，以下是计划，不是本轮已运行的命令。

```bash
cd server
uv sync --locked
uv run python -m unittest discover -s tests
docker compose config --quiet
docker compose up -d
```

Rust / 前端改动完成后：

```bash
pnpm build
cargo check --manifest-path src-tauri/Cargo.toml
```

真实验收使用本项目正式服务的开发运行方式。不得自动读取其他项目凭证、向未知服务器上传本机模型密钥、清理其他项目数据或创建种子演示数据。

## 停止点与回滚

- 规划停止点：本次 PRD/design/implement 的最小范围得到确认之前，不启动实现。
- 模型工具能力或真实服务配置不足：继续完成可验证的代码与静态检查，单独报告缺失的运行证据，不改用假模型作为完成证据。
- UI 并行改动冲突：停止覆盖，按最新文件与另一个任务的组件合同集成。
- 回滚仅涉及本任务新增服务与客户端接入代码；真实数据保留，所有数据库迁移及凭证撤销均按明确范围操作。
