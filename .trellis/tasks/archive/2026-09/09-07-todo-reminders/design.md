# Design

## Server contract
Migration004 adds nullable todos.remind_at TIMESTAMPTZ plus partial pending/due index, preserves current records. Todo adds remind_at: ISO offset string|null everywhere including tools. GET /v1/todos/reminders/due requires control; returns {items:Todo[]} pending AND remind_at <= now(), ordered by remind_at,id. It does not consume or mutate.
PUT /v1/todos/{id}/reminder requires control, exact body {remind_at: offset ISO string|null, expected_remind_at: offset ISO string|null}. Both keys required, extras rejected; non-null target must be in future (DB clock). Lock owned row in transaction; missing/foreign404, completed409. If current equals target, return existing item (retry). Otherwise current must equal expected or409. Then set target. Naive/nonfinite/invalid inputs400; target null clears. Use one real row transaction, no agent invocation. Complete clears remind_at in same existing update; reopen leaves it null. Extend existing fixture dictionaries conservatively.

## Native contract
Todo gains optional remind_at; View gains reminders:Vec<Todo>, reminder_error:Option<String>, todo_revision:u64 defaults. Add independent poll_reminders in existing start tokio::join!, 15s after each cycle; generation abort protects account changes. HTTP timeout/no redirects/native credentials. Due results are typed and must be pending with non-null reminder time. On failure retain prior reminders plus sanitized reminder_error; successful reads clear error. Publish only meaningful changes or use existing view revision ordering.
agent_set_todo_reminder(todo_id, remind_at:Option<String>, expected_remind_at:Option<String>) -> {generation,item}, PUT as above. Native validates safe UUID, response ID/pending and requested nullability; server owns timestamp parsing/comparison. On confirmed complete/reopen/set, remove item from cached due set and increment public todo_revision; normal next poll reconciles. Add private mutation epoch incremented before and after direct writes; due reads captured before a write must not overwrite cache afterward. Release mutex before awaits. Existing complete/model APIs preserved.

## Frontend contract and visible flow
src/lib/agent.ts shared Todo.remind_at:string|null, AgentView.reminders:Todo[], reminder_error:string|null,todo_revision:number; setTodoReminder(todoId,remindAt,expectedRemindAt) wrapper. Frontend implementer owns this shared TS file.
TodoList: pending row small Bell/time action opens inline datetime-local editor, save/cancel/clear with explicit labels, error and busy protection. Convert local date to ISO; show full localized scheduled time and current timezone hint. Save target and expected read value; on uncertain retry retain same attempted target until explicit new action. Existing completion controls intact; listen via refreshVersion prop driven by view.todo_revision for changes elsewhere without replacing frame.
New scoped reminder notice in existing expanded ChatPanel body (single bounded content wrapper if needed; do not change shared frame). Display due records and complete/snooze10m actions, preserve list/chat/settings navigation and drafts. Main App uses native View reminders; generation:id:remind_at identifies a due occurrence. Auto-expand existing main pet panel once per occurrence, retry after mode transition if opening was deferred. Do not auto-open hidden standalone chat window as well. Closing panel suppresses repeated auto-opening for same occurrence this process; future snooze time is new occurrence. Reconnect/restart catches up. Show syncing error without turning it into empty success. Avoid focus theft when user already editing. Action errors stay on same reminder; native update clears after success. Updates clear stale generation state.

## Conversational reminder tools

Extend todo.create registry version2 / todo_create schema with optional remind_at offset-ISO string (absent/null = ordinary todo). If non-null, create row and set reminder through shared transaction helper before finish_tool; all effects/result commit together, rollback both on failure. Add registered todo.reminder.set version1 / model todo_reminder_set exact args {todo_id,remind_at,expected_remind_at}; both times nullable, UUID/title/time strict validation. Refactor RuntimeStore.set_todo_reminder to delegate to set_todo_reminder_in_transaction(conn,account,id,target,expected), preserving direct HTTP semantics, locking/CAS/idempotence/DBclock checks. Handle ReminderConflict as a safe tool error, no secret exception text. Keep source_tool_call idempotence.

Settings.default_timezone defaults Asia/Shanghai, validated ZoneInfo; env PET_AGENT_DEFAULT_TIMEZONE. Agent per-run system context contains actual current timestamp and request created_at in that zone (relative times anchor request receipt); no hardcoded current date. Clarify missing/past local time before mutation, tool rejects past regardless. Current tool capabilities override old chat replies. Do not expose nonexistent timezone knowledge as device-local; default zone is explicit. No native/API protocol changes.

Frontend only updates tool names/result presentation for scheduled creation and reminder set/clear (localized explicit timestamp), and refreshes visible list after successful todo tool effects using a stable tool result revision/fingerprint in addition to existing native todo_revision. Do not remount ChatPanel or rewrite frames.

Owners: backend implementer server code/config/tools/tests; frontend implementer ChatPanel minimal tool rendering/list invalidation + pure helper if warranted; root specs/docs/probes/runtime. No new model executor or fake demo service, no real record writes for testing without target.
